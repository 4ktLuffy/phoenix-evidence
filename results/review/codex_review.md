## Code bugs / failing inputs

1. **Critical — xdist silently succeeds on a failed suite.** `test_xdist.py`: `@pytest.mark.evidence(threshold=.8)`, `@pytest.mark.parametrize('i', range(40))`, body `assert False`. Command in table returns 0 with strict mode. Expected nonzero and a single 40-case decision. Aggregate worker outcomes on the controller; only controller should write the report.
2. **Teardown crash is scored as success.** `@pytest.fixture` with `yield; raise RuntimeError('teardown')`, marked test body `pass`. In `test_plugin.py`, this contributes True. Expected failure. Also `@pytest.mark.xfail(run=False)` vanishes from the decision; pre-call skip policies need explicit definition.
3. **Gate point estimate uses a different estimand from its interval.** `decide_rate([[True]]*40 + [[False]*1000], .8)` → `PASS: 0.038 [0.871,0.999] ... 41 examples`. Failing invariant: estimate must lie within its reported interval. Example-weighted estimate should be 40/41, not 40/1040.
4. **Per-class recall uses majority votes, not judgment shares.** `agreement([[('a','a'),('a','b')]]*20 + [[('b','b'),('b','a')]]*20, resamples=200)` → accuracy/balanced accuracy `.5`, but each class recall `20/20`, CI `[.83157,1]`. Failing assertion: a 50%-correct class must not report 100% recall. Ties count as correct. Document a distinct majority-vote metric or compute recall consistently.
5. **Sign-flip inference advertised for the wrong null.** Failing distribution D∈{.1,−.9}, probabilities {.9,.1}, n=16; zero mean yet rejection ≥.1853 at alpha=.05. Exact enumeration itself is correct under sign symmetry; API documentation and broad guarantee are not.
6. **Empty crash representations escape default missing scoring.** `compare({'ok':[1],'crash':[0]}, {'ok':[1],'crash':[]}, bootstrap=100)` reports one paired example and zero missing B judgments. `[None]` retains both. Failing expectation under the broad crashed-run promise: an empty recorded case should not silently disappear. Either reject empty sequences or state that only explicit None is a crash.
7. **Power search skips the first acceptable n.** `examples_to_pass(.75,.7)` returns 663 although all `pass_probability(m,.75,.7)>=.8` for m=662…681. Likewise 495 instead of 494 at .85/.8. Failing documented-minimum assertions are `==662` and `==494`.
8. **Phoenix patch/schema mismatch: runs versus examples.** Scratch `run_count_test.py` is the supplied test with expected equals `3*repetitions`. At repetitions=2, six actual base runs produce only three equal counts. Best-per-example is a defensible design, but requires an explicit schema/semantic change. More generally, base repetitions of latency 30s and 10s against compare best 10s yield only one equal example, omitting the slower base run's regression.
9. **Phoenix incomplete costs look cheaper.** Scratch `partial_cost_test.py` changes only base `total_cost` to `None` for span j=0. Assertion “three withoutComparison” fails: `[NULL,1]` beats `[1,1]`. Inherited SUM/NULL behavior, not a demonstrated newly introduced regression. This bug assessment assumes NULL denotes unknown cost, not intentional zero; make that policy explicit.
10. **Injection benchmark pseudo-replication.** Input 23 cases with three identical repeats per case, two cases always flip. `results/injection_refusal.json` uses 69-trial confidence intervals; expected case-level bounds are in the table. This is a benchmark statistical bug, not an error in the integer counts or p=.5.
