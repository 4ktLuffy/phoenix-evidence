## Code bugs with failing inputs

1. **High — same-data PPI tuning is biased.** `_ppi.corrected_rate([0,0,1], human, [1,.3,.7])`, true labels `[0,0,1]`, independent draws. Index 0 is always labelled. If index 2 is absent, weight=0 and estimate=0; if present, weight=1 and estimate=1/3. Thus expectation=.7/3, not 1/3. No empty-sample conditioning or clipping is involved. Fixed, label-independent weight λ gives the unbiased estimator `N⁻¹ Σ[λfᵢ + Iᵢ(yᵢ−λfᵢ)/πᵢ]`; this implementation does not keep λ fixed. Bounding the returned estimate adds another source of bias.

2. **High — invalid design variance/coverage claim.** For fixed λ and independent Bernoulli inclusion, true design variance is `N⁻² Σ ((1−πᵢ)/πᵢ)(yᵢ−λfᵢ)²`; its usual unbiased sample estimator replaces each summand by `Iᵢ(1−πᵢ)(yᵢ−λfᵢ)²/πᵢ²`. The code instead uses `sample_variance(z)/N`. For fixed λ its expectation includes an additional `sample_variance(y)/N`; tuning and the ad hoc floor have no design-coverage guarantee. Failing population: `judge=[0]*100`, humans `[0]*50+[1]*50`, inclusion `[1]*50+[.0001]*50`, seed 8675309. **6/2,000** intervals cover .5. Every probability is positive; no missing chosen labels. The guard's use of **mean** π cannot protect the rarely sampled stratum.

3. **Medium — confidence intervals can be reversed/outside [0,1].** `corrected_rate([0]*100, {i:1 for i in range(50)}, [.01]*100)` returns estimate **1**, interval **[39.886,1]**, same broken human-only bounds. Only one end of each bound is clipped; a legal, albeit rare, Bernoulli realization is enough. Input validation is also incomplete: a short inclusion vector can silently succeed when omitted entries are unlabelled; out-of-range human indices raise `IndexError`; `plan_labels([0,0],1,floor=0)` divides by zero.

4. **High — unfinished reviews silently treated as zero residuals.** `corrected_rate_from_plan`: choose all 100 with π=1, judge all `no`, all humans actually `yes`, return reviews for only indices 0…49. It returns **.5 [.385,.615]**, although truth=1. `still_to_label` lists the missing reviews but does not prevent the invalid estimate. Selection probability is not observation probability when chosen humans do not respond.

5. **High — correction silently changes the planned population/predictor.** Plan `population=chosen=['a','b']`, π=1 each; surviving annotations are judge `a=yes`, humans `a=yes,b=no`. Adapter returns **spans=1, chosen=2, labelled=1, still_to_label=[], estimate=1**, instead of the planned population's .5. This can occur through the very UI overwrite described in §6, or pagination. The plan also does not freeze all judge predictions: later annotations can change the predictor after human feedback.

6. **Medium — human aggregation remains inconsistent.** Same span: LLM `yes`, HUMAN `yes`, HUMAN `no` under the separate review name. `pairs_from_span_annotations` includes both; certificate accuracy=.5; `feedback_certificate.disagreements=[]` because it keeps the first human only. Correction keeps the last human instead. Annotation order therefore changes exported disagreements/corrections. `judge_identifier` does not resolve multiple human annotators.

7. **Low — “latest” compares timestamp strings, not instants.** Two matching LLM annotations: `old` at `2026-01-01T10:00:00+02:00`, `new` at `2026-01-01T09:00:00+00:00`. `judge_labels` returns **old**, although new is an hour later. Reproduced with fake client inputs; impact depends on server timestamp normalization.

8. **High — actual Phoenix repetitions shrink the interval.** `acceptance.ts` groups by `result.testName`; `runner.ts:181–194,285` assigns `${uniqueName} [rep ${rep}/${repetitions}]`. Ten perfect examples repeated three times become 30 examples and pass bar .8, whereas ten examples are undecided. Scratch Vitest reproduces the failure; the supplied test's identical names conceal it. Carry/use the logical example identity.

9. **High — missing minimized scores become successes.** Sixty distinct `status:'passed', annotations:[]` results; criterion `{annotationName:'q',metric:'average',direction:'minimize',threshold:.1,interval:{}}`. Returns **PASS**, missingCount=60. Missing normalized minimize scores must not become 0. This is independent of failure status or repetition grouping.

10. **High — GraphQL fabricates baseline scores for an evaluator never run there.** Twenty shared examples, base has no `q` annotations, candidate `q=i/19`. Real resolver with fake SQL result rows returns **BETTER**, p≈.00005; absent baseline becomes twenty zeroes. CLI's `only_in` behavior already avoids this. Label-only annotations mixed with numeric annotations across experiments have the same comparability problem. Holm cannot repair invented observations.

11. **Medium — upstream evidence assumes scale/direction it does not require.** `compare_scores({a:[0],b:[1]}, {a:[1],b:[1]})` needs **14** examples; multiplying every score by 100 changes this to **None** despite unchanged standardized evidence. The paired-proportion planning formula is applied to arbitrary annotation differences/repetition means. Separately, ten `error_rate` scores increasing from 1 to 2 get verdict **BETTER**; missing runs use numeric minimum even for costs/errors. Either constrain/document supported metrics or carry direction and use suitable planning. “Worst score seen” is also only an observed imputation convention: if every observed score is 1, a missing run is imputed 1, not a demonstrated failure.

12. **Medium — worker death loses completed failing outcomes from the report.** Forty parametrized evidence tests all assert false except case 15 calls `os._exit(17)`. With `-n 2`, pytest records **39 xfailed + 1 crashed**, but the evidence JSON has **34 judgments, missing=0**. Outcomes are sent only from worker `pytest_sessionfinish`, which a crash never executes. The controller should collect reports incrementally or explicitly invalidate/incomplete-mark the aggregate. Session failure is preserved by xdist, so no successful CI bypass was demonstrated.
